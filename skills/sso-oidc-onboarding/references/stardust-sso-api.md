# Stardust SSO API Reference

Default issuer:

```text
https://sso.corpintra.rosettalab.top
```

OIDC endpoints. Generated clients must fetch discovery first and use the returned endpoint metadata, especially `jwks_uri`, instead of hardcoding JWKS as the primary source:

```text
Discovery: /.well-known/openid-configuration
Authorize: /oauth/authorize
Token: /oauth/token
UserInfo: /oauth/userinfo
Introspection: /oauth/introspect
Logout: /oauth/logout
JWKS fallback: /api/sso/v1/jwks
```

## Admin-Managed Company Project

Endpoint:

```http
POST /api/company-projects
Content-Type: application/json
Cookie: stardust_sso_sid=<session>
```

Requires either an admin browser session with MFA and `projects:manage`, or a user API token with `projects:create` scope.

Automation should send the user API token that Codex saved locally after the user created it in SSO:

```text
https://sso.corpintra.rosettalab.top/?tab=tokens&scope=projects:create&tokenName=Codex%20OIDC%20Onboarding
```

Send the saved token as the HTTP bearer token in the `Authorization` header.

The token only authorizes the scopes granted when it was created. For this workflow, require `projects:create`.

Useful request fields:

```json
{
  "name": "业务系统",
  "description": "公司统一接入项目",
  "serviceUrl": "https://app.example.com",
  "callbackUrl": "https://app.example.com/sso/callback",
  "redirectUris": ["https://app.example.com/sso/callback"],
  "protocol": "oidc",
  "category": "business",
  "clientId": "app-example",
  "publicClient": false,
  "scopes": ["openid", "profile", "email", "groups"],
  "groups": []
}
```

Response shape:

```json
{
  "project": {
    "id": "company_xxx",
    "clientId": "app-example",
    "clientSecret": "sec_xxx",
    "clientSecretPreview": "sec_xxx...xxxxxx",
    "callbackUrl": "https://app.example.com/sso/callback"
  }
}
```

`clientSecret` is returned only on creation or reset. Persist it immediately outside source control.

## Self-Service Custom Integration

Endpoint:

```http
POST /api/integrations
Content-Type: application/json
Cookie: stardust_sso_sid=<session>
```

Use this only for user-owned custom integrations, not company-wide managed projects.

Request fields are similar, but `clientId` is generated by SSO:

```json
{
  "name": "业务系统",
  "description": "业务平台描述",
  "type": "oidc",
  "serviceUrl": "https://app.example.com",
  "callbackUrl": "https://app.example.com/sso/callback",
  "redirectUris": ["https://app.example.com/sso/callback"],
  "allowedDomains": ["app.example.com"],
  "publicClient": false,
  "scopes": ["openid", "profile", "email", "groups"]
}
```

Response has `integration.clientId` and, for confidential clients, `integration.clientSecret`.

## OIDC Flow Notes

Callback URLs are exact string matches. Register every environment callback separately; do not use wildcards.

Local development callbacks may use loopback HTTP URLs such as `http://localhost:3000/sso/callback`; these are development-only and visible only to the requesting user. Production clients must be registered separately with the real HTTPS service URL and HTTPS callback URL.

Confidential token exchange must default to `client_secret_basic`:

```http
POST /oauth/token
Authorization: Basic base64(client_id:client_secret)
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&code=<code>&redirect_uri=<exact-uri>&code_verifier=<pkce-verifier>
```

Public clients must use PKCE S256 and send `client_id` plus `code_verifier`; they do not receive or store a secret.

Before token exchange, validate `code_verifier` locally:

- Length must be 43-128 characters.
- Characters must be limited to `[A-Za-z0-9._~-]`.
- Reject invalid verifier values before calling `/oauth/token`.
