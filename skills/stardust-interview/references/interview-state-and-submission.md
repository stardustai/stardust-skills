# 面试状态与提交目标

面试排期、面试记录、听记和提交授权是四类独立状态。不要用其中一类状态推断另一类。

## 四类状态

| 状态 | 事实源 | 正确含义 |
|---|---|---|
| 面试官与时间排期 | `get_interview_context` 完整评审包的“面试安排时间” | 面试官已填写表示该轮已分配；时间为空只表示尚未填写时间 |
| 面试记录 | `list_candidate_interviews` | 是否已有可供 MCP 更新的 `interview_id`，不代表是否安排或是否完成面试 |
| AI 听记 | DWS `minutes` | 是否已有足够证据生成面评，与小青是否已有记录无关 |
| 提交授权 | 当前线程中面试官的明确确认 | 是否允许写入小青；自动任务不能自行推定授权 |

使用准确措辞：面试官已填写、时间为空时，应说“该轮已分配给 Derek，时间未填写”，不要说“未安排”。

## 状态决策表

| 排期/归属 | 目标轮记录 | 听记 | 动作 |
|---|---|---|---|
| 已分配 | 已有 | 已有 | 生成面评；确认后刷新 revision，MCP dry run 后正式提交 |
| 已分配 | 没有 | 已有 | 正常生成面评；确认后用网页该轮“填写评价”创建并提交，再读回新 ID |
| 未分配 | 没有 | 已有 | 用户已明确指定候选人和轮次时仍可生成面评；确认后用网页创建该轮记录，不要求 HR 先补排期 |
| 任意 | 任意 | 没有 | 只报告听记尚未就绪；继续定时回查，不凭空评价 |
| 任意 | 只有其他轮次记录 | 已有 | 绝不复用其他轮次 ID；按目标轮创建或等待确认提交 |

只有候选人不唯一、目标轮次不明确、权限/认证失败或用户尚未确认提交，才是实际阻塞。缺少目标轮 `interview_id` 本身不是阻塞，也不是招聘群通知事项。

## 无 interview_id 的提交路径

当前 `upload_interview_result` 只能更新已有记录。目标轮次没有记录时，按网页端业务能力处理：

1. 打开候选人详情页的“面试安排及面评记录”。
2. 在目标轮次点击“填写评价”。
3. 核对候选人、岗位、轮次和面试官；时间可以为空。
4. 填写已确认的推荐结论、总评、风险、全部专业评分及评分理由、全部价值观评分及评分理由，并附符合授权范围的听记依据。
5. 提交后调用 `list_candidate_interviews`，确认新增记录的 round、interviewer、recommendation、score 和 revision。
6. 若读回结果不一致，报告写入异常；不要重试到其他轮次。

网页创建记录属于小青正式写入，仍需用户先确认完整面评。不要因为改走网页就跳过确认。

## 自动复盘任务

自动任务以 `candidate_id + target_round` 定位目标，`interview_id` 仅在已存在时附加：

- prompt 必须包含候选人姓名、岗位、candidate_id、目标轮次和面试官；有 interview_id 时再包含该 ID。
- 每次运行先刷新 `get_interview_context`，再刷新 `list_candidate_interviews`。
- 没有目标轮记录时继续检索 DWS 和生成草稿，不通知 HR 补记录。
- 只有线程里已经存在对该版面评的明确提交确认，自动任务才可写入。
- 提交成功后按新 ID 读回并取消该候选人该轮任务。

## 回归场景

1. 完整评审包显示“二面面试官 Derek、时间为空”，列表只有一面：结论必须是“二面已分配给 Derek，记录尚未生成”，并继续拉听记。
2. 完整评审包和列表都没有二面记录，但用户明确要求提交二面评价：不得复用一面 ID或要求 HR 建记录，应走网页“填写评价”。
3. 列表已有二面 `status=scheduled`：使用该 ID 和最新 revision 走 MCP dry run；不得把默认 0 分或默认推荐值当成已有面评。
