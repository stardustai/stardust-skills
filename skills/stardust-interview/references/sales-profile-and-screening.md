# 产品与解决方案型销售：画像及前置筛选

## 适用范围

用于解决方案销售、销售工程师及当前北京 KA 招聘。先对齐实际岗位、级别和要卖的业务，再按候选人经历选择筛选路径。此文只规定考察门槛，不改变小青原生权重，不自动修改岗位或作出录用决定。

## 优先能力结构

| 能力 | 必须看到的行为 | 不能替代它的标签 |
|---|---|---|
| 客户价值直觉 | 从真实流程、成本、失败或行为发现未满足问题，识别受益者及付费方 | 客户名单、KA 级别、关系深 |
| 产品思维 | 定义需求、比较替代方案、做取舍，解释不卖什么及原因 | 功能多、技术新、市场热 |
| 解决方案思维 | 将问题转为数据条件、试点、验收及交付边界，能翻译客户与技术语言 | 做过 PPT、参与过 PoC、协调过售前 |
| 结果责任 | 个人获客、明确下一步、商务承诺、合同、验收、实收、续单 | 团队合同额、预算总额、Token 消耗或线索数量 |
| 学习与动机 | 亲自体验及研究，识别错误并复盘，愿意面向客户承担商业结果 | 会用 AI、产品或技术头衔、接受低薪 |

可以优先考察产品、售前、技术转销售的复合型人选，但“懂产品”不等于“会销售”。对转行者验证潜力与带教条件，不虚构成熟成交经验；对资深销售要求真实、可拆解的本人订单。

## 路径 A：有经验的销售

必问题：

> 你最擅长哪类客户画像？他们当前最重要、尚未被满足的痛点是什么？请用你亲自接触的客户说明。

递进追问：

1. 哪类公司、哪个部门、哪个角色、哪段流程？你最近如何得知这个痛点？
2. 现在怎样解决？为什么还不够？造成什么损失，谁负责、谁会付费？
3. 哪部分适合 AI，为什么比规则、传统软件或流程改造更有价值？需要什么数据，怎么验证，失败怎么办？
4. 你本人做过什么动作来验证需求、获得下一步承诺？对应订单如何签约、验收、回款？

通过依据：具体客户与当前问题、本人证据、付费逻辑、可验证的下一步同时成立。历史数据库或资源销售经验可保留，但不能直接替代数据解决方案能力。

不通过示例：“我熟银行和央企，有领导关系，客户都有智能化需求，所以可以卖知识库。”缺少真实流程、未满足问题及购买理由，不能进入 Derek 面试。

## 路径 B：转行的销售工程师

必问题：

> 哪个或者什么样的 AI 产品你觉得好卖？为什么？

允许选具体产品或类型，不设唯一正确产品。追问以下内容，不考背概念：

1. 卖给谁、谁用、谁买单？解决什么当前问题，为什么现在会买？
2. 客户已有免费或人工替代方案，为什么还愿意付费？AI 的增量价值是什么？
3. 你亲自用过、看过或验证了什么？哪些是事实、哪些还是假设？
4. 从哪里找到前几位客户，第一次问什么？最小试点如何验收？
5. 客户要求免费做、效果不可验收或迟迟不采购时，如何界定投入和退出条件？如何推进合同、验收和回款？

通过依据：能把产品选择连接到用户问题、付费动机、替代方案、验证及商业推进；可以没有历史销售订单，但要有一手体验或项目材料和可检验的设想。通过只代表潜力可继续考察，不代表自拓或成交已被验证。

不通过示例：“选最火的 Agent，用户很多，价格便宜，AI 能降本增效。”有产品热度，没有价值与购买判断，不进入 Derek 面试。

## 分类与排期

- HR/前轮按实际经历选择 A 或 B，记录理由；不以“销售总监”或“产品经理”头衔代替分类。
- 有经验的销售不能因 A 不通过而改走 B 绕过门槛；混合背景保留实际销售责任的核验。
- 对应问题未过关，不安排 Derek；先由 HR/前轮补测并保存新证据，不能把 CEO 轮当作补做初筛。
- 销售经验少不自动淘汰，产品能力强不自动通过。级别、薪资、可独立完成部分、带教及验证条件分开记录。
- 不要求外泄客户机密或私人通讯记录；可用脱敏案例、本人动作及经授权材料核验。

## 前轮交接记录

交给 Derek 的材料须包含下列字段，不能只给“沟通好、推荐”：

| 字段 | 内容 |
|---|---|
| 实际岗位、级别及业务 | 当前要卖什么、是否匹配候选人背景 |
| 筛选路径与理由 | A 或 B，依据实际职责 |
| 必问题及本人回答 | 保留原文或忠实摘录及来源，不用面试官讲解替代 |
| 递进追问与证据 | 当前痛点/产品判断、替代方案、付费与验证逻辑 |
| 自拓、成交、回款状态 | 分别为已证明、待验证或不达标；未做过不写已完成 |
| 门槛结论 | 通过/未通过、具体理由，未通过不得排 Derek |
| 下一轮重点 | 尚未验证且会影响录用的事项、通过标准及带教边界 |
