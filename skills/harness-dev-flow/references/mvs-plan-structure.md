# MVS-Plan 结构模板

MVS-Plan 把系统切成有依赖顺序的最小可验证切片（MVS）。依赖链在此阶段定死，未排清不准动编码。

## 章节骨架

```
# <项目> MVS Plan

## 1. 拆分原则
  - 按"用户可观察的业务行为"拆，不按目录/类/表拆
  - 每个 MVS 能独立运行和验证，对应 PRD 的 FR
  - 开始前确定全部 MVS 的目标/依赖/验收，但不提前拆完所有代码任务
  - 颗粒度规则（见下）
  - 同一时间只详细实现一个 MVS
  - 新发现可调整未开始 MVS，但不得无记录改变已完成切片的验收结果
  - 技术探针不算 MVS，但必须在第一个 MVS 前完成
  - 前端最后实现

## 2. 总体状态与顺序
### 2.1 状态定义          ← 表：待开始/进行中/待验证/已完成/阻塞
### 2.2 切片总览          ← 表：顺序 | 切片 | 用户可观察结果 | 对应PRD | 状态
### 2.3 依赖关系          ← mermaid flowchart

## 3. SP-00：关键技术探针
### 目标 / 探针内容 / 通过条件 / 实际结论 / 失败时的处理

## 4..N. 每个 MVS
### 用户可观察行为
### 本切片范围
### 不在本切片范围        ← 显式划界，防蔓延
### 验收标准
### 验证证据              ← 完成后回填

## 滚动细化与更新规则
### 开始一个切片前（5 步）
### 完成一个切片后（7 步）
### 允许修改的内容
### 必须回到 PRD/技术Plan 确认的变化   ← 删可观察结果/降安全标准/加场景/加依赖/扩成平台

## 当前唯一下一步          ← 单一焦点，完成后更新
```

## 颗粒度规则（关键不变量）
- 从第二个 MVS 起，最细执行单元固定为 `MVS-xx-yy`，不再拆 `MVS-xx-yy-zz` 三级。
- 内部工作清单不形成独立编号、ExecPlan 或进度状态。
- 当前单元未通过，不进入下一单元。

## 依赖链排序心法
地基 -> 前置能力 -> 上层能力 -> 交付。参考样例链：
`SP-00 探针 → MVS-01 行走骨架 → MVS-02 动态查询 → MVS-03 检索 → MVS-04 核验 → MVS-05 会话/恢复 → MVS-06 展示与整体验收`
每一步为下一步解锁更复杂能力，且本身可独立验收。
