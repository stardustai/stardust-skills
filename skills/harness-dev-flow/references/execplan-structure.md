# ExecPlan 结构模板

每个 MVS 开始实现前写一份 `MVS-xx-ExecPlan.md`，固定本切片执行边界。无 ExecPlan 不编码。

## 章节骨架

```
# MVS-xx <切片名> ExecPlan

## 1. 当前状态
  - 计划状态 / 上游条件 / 当前执行单元 / 下一个单元

## 2. 本单元要解决的问题
  - 现状能回答什么，但不能回答什么（逐条列）
  - 本单元产出的可复用契约是什么

## 3. 调查事实
### 3.1 证据来源        ← 具体文件/评测集/基线 SQL/migration
### 3.2 事实分类        ← 把混在一起的东西归一化为原子类别（表格）

## 4. 矛盾分析（可选，接入思想武器）
### 4.1 矛盾清单        ← [A] vs [B]，标 ⭐ 主要矛盾
### 4.2 主要矛盾与性质   ← 对抗性/非对抗性、主要方面、应对方法
  ⚠️ 需监控：<可能上升的矛盾>

## 5. <语义/业务>边界
  - 维度匹配 / 度量口径 / NULL 与缺失 / 粒度与去重 / 排序与 Top-N
  - 明确"必须拒绝"的项，不估算

## 6. 执行单元拆分
  - MVS-xx-01 ... 每个单元：输入 / 动作 / 预期输出 / 实际验证方式
  - 当前单元未通过不进下一个

## 7. 验收方式
  - 指向本 MVS 的可重复验收单元
```

## 要点
- "调查事实"和"矛盾分析"段落可调用 `investigation-first` / `contradiction-analysis`，但结论写回本文件，不留在对话里。
- 边界段落要显式列出"必须拒绝/不估算"的项--这是模型节点无事实权威的体现。
- ExecPlan 是意图和边界，不是实现细节；实现留给 agent。
