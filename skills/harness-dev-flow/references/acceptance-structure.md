# 可重复验收结构模板

每个 MVS 以一份可重复验收收尾。这是 Harness 的"反馈回路"在单人流程里的落地：从空环境、固定输入重建，得到可复现结论并留证据。未通过不进下一 MVS。

## 章节骨架

```
# MVS-xx-<末> 可重复验收与阶段审视

## 1. 验收目标
  - 终止条件清单（编号列，每条可判定）

## 2. 隔离方式
  - 资产隔离表：资产 | 隔离位置/方式
    （Python 环境、依赖缓存、数据库、SQL 结果、运行记录、原始输入、模型端点）
  - 明确"从空环境"指什么、不指什么（如不指重新抓取变化的外部 API）

## 3. 重建结果
### 3.1 工程环境      ← 版本、sync 结果、health 检查、是否输出凭证
### 3.2 数据库        ← 版本、迁移、表数、权限反向测试（写入/DDL 被拒的 SQLSTATE）
### 3.3 固定数据      ← 重建计数；重复导入 count_delta=0；外键孤儿检查=0

## 4. 正式 Agent 结果
  - Run ID / 模型 / 可观察状态流转 / Task ID / Result ID
  - Result SHA-256
  - 输出计数、来源、耗时、错误数
  - 与人工基线的深度比较结论

## 5. 质量门
  - 表：检查 | 结果（测试 passed 数、lint、格式、lock 检查、JSON 证据、数据库复验）

## 6. 完成定义审计
  - 表：完成条件 | 证据 | 结论
  - 末句：MVS-xx 满足完成定义，可标记为已完成

## 7. 工作审视报告
  - 原定目标 / 实际结果 / 偏差与原因 / 后续影响
```

## 证据纪律（来自用户原则）
- 保留相对路径、哈希、计数、脱敏摘要。
- 不写凭据、绝对本地路径、完整 SQL、对话正文或源文档正文。
- 离线确定性验收与真实模型质量分开披露；不删题、不改分母、不伪造结果掩盖失败。
- "passed=true"指离线可复现，不等于真实模型门禁通过，二者分别报告。
