# 生产就绪要求

## 目录

1. 迁移安全
2. 持久性和恢复
3. 权限和敏感数据
4. 运行可靠性
5. 可观测性
6. 扩展能力
7. 发布门槛

## 迁移安全

- 使用仓库已有迁移工具和命名约定。
- 区分全新安装基线和生产增量迁移。
- 不得把破坏性变更隐藏在替换版 `CREATE TABLE` 脚本中。
- 风险较高的字段或关系变更优先使用“扩展、回填、切换、收缩”流程。
- 回填任务要可重启、可观察，并明确新写入如何处理。
- 使用接近生产的数据量评估锁、表重写、索引创建行为和迁移时长。
- 定义前滚和回滚边界。破坏数据的迁移通常无法真正回滚。
- 种子或 Demo 数据与 Schema 迁移分开，不得包含真实个人数据。

## 持久性和恢复

- 明确数据是可丢弃、可重建还是权威数据。
- 定义备份频率、保留时间、加密和负责人。
- Production 和 Critical 系统要定义 RPO、RTO，不能只写“已开启备份”。
- 在隔离环境实际执行恢复，并验证应用层完整性。
- 把辅助存储纳入恢复设计，或者说明如何重建。
- 复制用于提高可用性，不能替代备份。

## 权限和敏感数据

- 需要时分别使用最小权限的运行账号、迁移账号、只读账号和管理账号。
- 凭据放在批准的密钥系统中，不得写入代码、DDL 注释或示例。
- 网络访问的生产数据库必须加密传输。
- 敏感系统评估静态加密和密钥归属。
- 定义租户隔离、特权绕过路径、审计、保留、导出和删除要求。
- 避免应用账号拥有过宽权限，避免数据库直接暴露公网。

## 运行可靠性

- 根据数据库连接上限和部署并发定义连接池大小。
- 有意识地设置连接、语句、锁和事务超时。
- 控制事务范围；只有操作确定安全或幂等时才自动重试。
- 定义重复请求、死锁、故障切换、只读副本滞后和辅助存储不可用时的行为。
- 在应用边界阻止 N+1 查询和无上限结果集。

## 可观测性

按照项目等级监控：

- 可用性和连接失败；
- 连接池饱和和连接数；
- 查询延迟和慢查询；
- 锁等待、死锁和长事务；
- CPU、内存、存储、I/O 和增长速度；
- 备份和恢复状态；
- 复制或数据摄取延迟；
- 迁移进度和错误；
- 辅助缓存或搜索的命中率和重建健康度。

告警要能够对应用户影响和可执行的运维动作。

## 扩展能力

没有证据和负责人时，不引入：

- 只读副本；
- 表分区；
- 应用或数据库分片；
- 分布式 SQL；
- 双活写入；
- 跨区域副本；
- 独立搜索、向量、时序或分析存储。

每项能力都要说明可度量触发条件、故障行为、一致性取舍、运维负责人和移除或回滚路径。

## 发布门槛

宣称生产 Schema 就绪前，至少要求：

- 从当前生产版本升级以及全新数据库安装两条路径都完成迁移测试；
- 根据真实查询路径审查约束和索引；
- 关键查询具有代表性的执行计划；
- 有备份恢复证据；
- 权限和租户隔离已经验证；
- 保留和删除行为已经测试；
- 监控以及迁移回滚或前滚流程已准备；
- 未解决风险已经明确负责人。

Critical 系统必须由合格专业人员审查。Skill 可以提供辅助，但不得把自己描述为最终合规、安全或可靠性责任方。
