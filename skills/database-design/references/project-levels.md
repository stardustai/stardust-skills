## 独立分类维度

分别判断以下维度：

- **用户能力**：决定术语、教学深度和实施指导的详细程度。
- **项目等级**：决定持久化、迁移、测试和运维保护标准。
- **数据敏感度**：决定安全、隐私、审计、保留和访问要求。
- **运维责任**：决定某种数据库是否真的有人能够维护。

不得用岗位代替上述判断。后端工程师可能只是在做可丢弃 Demo；HR 也可能在构建包含高风险真实数据的员工系统。

## 解释模式

### 业务模式（business）

适用于产品、运营、HR、招聘、销售等不需要数据库术语的业务用户。

- 先讲业务对象、规则、风险和结论。
- 把技术取舍翻译成用户能感知的后果。
- 在 DDL 前展示数据字典和关系。
- 不直接询问隔离级别、基数或索引类型。
- 用户要求实现时，仍然交付完整工程产物。

### 构建模式（builder）

适用于前端开发、Vibe Coding 用户、自动化搭建者和全栈初学者。

- 先给出一个安全默认方案并说明原因。
- 生成可复制、符合目标方言的 DDL 或迁移。
- 把约束、索引与对应功能或查询一起解释。
- 有帮助时补充本地搭建和升级路径风险。
- 没有具体需求时，不增加额外基础设施。

### 工程模式（engineer）

适用于后端、数据、平台、SRE 和架构人员。

- 补充事务边界、查询模式、索引顺序、迁移策略和运维取舍。
- 区分逻辑模型、物理设计和部署决策。
- 有证据时量化假设。
- 给出验证命令和执行计划预期，但不得冒充已经执行。

## 项目等级

### Demo

仅当数据可丢弃或可重建、用户很少、主要用于演示或学习时使用。

最低保护：

- 清晰的 Schema 和说明；
- 主键和必要完整性约束；
- 只建立有明显查询依据的索引；
- 明确说明未评估生产就绪性；
- 如果预计继续演进，说明迁移路径。

### Prototype

用于数据需要保留、相关人员会试用真实流程，但还没有严格可用性承诺的原型。

额外要求：

- 迁移工具和可复现搭建方式；
- 备份预期；
- 认证和授权边界；
- 敏感数据分类；
- 并发假设；
- 迁移到预期生产引擎的可信路径。

### Production

用于真实用户或业务数据依赖该系统的项目。

额外要求：

- 经过审查的迁移和安全发布策略；
- 备份以及恢复测试；
- 最小权限、密钥管理和监控；
- 明确的数据保留和删除语义；
- 连接池、超时和故障行为；
- 对关键路径使用代表性数据验证执行计划和负载。

### Critical

用于受监管、财务、薪资、凭据、健康、安全、高影响多租户数据，或者停机、丢数据会造成重大后果的系统。

额外要求：

- 明确 RPO、RTO 和故障域假设；
- 可审计性和职责分离；
- 加密和密钥管理责任人；
- 租户隔离验证；
- 恢复、故障切换、事故响应和删除证据；
- 上生产前必须由合格专业人员审查。

不要仅因为“以后可能变大”就把系统标为 Critical。只有后果、监管或明确的可用性和恢复要求才能触发升级。

## 数据敏感度升级

以下数据会独立提高风险：

- 身份和联系方式；
- 候选人、员工、薪酬、绩效或处分记录；
- 财务账户和交易；
- 凭据、Token、会话和恢复数据；
- 健康、生物识别、位置或其他受监管数据；
- 租户机密业务数据。

如果 Demo 使用真实敏感数据，即使应用是临时的，数据处理也必须采用 Production 或 Critical 级保护。

## 最小信息收集

只收集或推断会改变决策的信息：

- 要构建什么，数据是否可丢弃；
- 谁读取、谁写入，是否存在并发写入；
- 核心实体、关系和不变量；
- 重要筛选、排序、关联、报表和搜索；
- 当前数据量和可信的未来范围；
- 事务和一致性要求；
- 部署方式和团队能够维护的技术栈；
- 敏感度、保留、备份和恢复预期；
- 运维责任人和预算约束。

把可见仓库的依赖或配置作为证据前，先确认它属于用户所说的应用。当前工作目录本身不能证明项目范围。

每次最多询问三个问题。优先使用仓库证据和用户能理解的表达。

## 把数据库术语翻译成业务问题

| 要确认的事项 | 面向业务用户的问题 |
|---|---|
| 并发写入 | 是否会有多人或自动任务同时修改同一批记录？ |
| 事务原子性 | 哪些修改必须全部成功，或者全部失败？ |
| 一致性 | 更新后短时间看到旧数据是否可以接受，会造成什么后果？ |
| 规模 | 当前大约有多少条记录，明年合理的上限是多少？ |
| 恢复 | 服务故障时最多能接受丢失多长时间的数据，多久必须恢复？ |
| 查询模式 | 最常用的页面、筛选、排序、搜索和报表是什么？ |
| 保留 | 记录什么时候归档，什么时候必须永久删除？ |
| 多租户 | 是否必须从技术上保证一个客户看不到另一个客户的数据？ |
