# 数据适配协作问答

面向 PM 回答导入、导出、报错、PM-check 和交付问题。目标是让 PM 少走弯路，并把需要开发判断的问题整理清楚。

## 总原则

- 导入是把客户数据整理成平台能创建任务的格式。
- 导出是把平台标注结果整理成客户要接收的格式。
- 导入和导出是两条不同口径，不要强行合并理解。
- 平台报错不等于脚本有问题；可能是数据格式、任务模板、标签配置、路径权限、平台服务或脚本输出问题。
- 真实平台报错原文如 `uuid`、`uniqueIdentifier`、`annotation`、`操作项不存在`、`节点顺序不一致`，优先看 `platform-errors.md` 的 PM 口径。
- 工具跑完不等于交付完成；交付前要看格式、数量、映射、抽样和客户验收口径。

## PM 问：导入 JSONL 里的任务标题从哪里来？

答法：

`metadata.title` 通常是平台任务展示和追踪用的标题。它可能来自源文件名、TXT 任务清单里的任务名，或导航 JSON 文件名。不能默认写在顶层，也不能只看文件名猜，要看当前导入工具的约定。

让 PM 提供：

- 使用的导入工具或页面。
- 输入 TXT 或源文件样例。
- 输出 JSONL 任意一行样例。
- 平台上任务展示截图。

需要开发确认：

- 新脚本、新客户、新任务类型。
- PM 要求改标题来源、拆分规则或唯一 ID 规则。

## PM 问：一个 JSONL 文件应该放多少任务？

答法：

JSONL 只是“一行一个 JSON 记录”的文件形式；一行到底代表一个任务还是一帧，要看当前工具。每个 JSONL 放多少任务是批次切分参数，不是固定行业规则。

让 PM 提供：

- 总任务数。
- 平台单次导入限制。
- 期望每个文件最大任务数。
- 是否需要按项目、日期、clip 或客户批次分开。

## PM 问：预标注导入失败是不是代码问题？

答法：

不一定。预标注失败常见原因包括：预标注文件格式不对、路径不可访问、OSS 配置问题、任务模板不匹配、平台标签配置不一致、脚本输出字段不符合平台要求。

让 PM 先收集：

- 完整报错文本和截图。
- 输入根路径、预标注文件路径、输出 JSONL 路径。
- 项目、任务类型、标签模板。
- 失败发生在上传、解析、创建任务还是提交后。
- 1-2 条失败样本，不要直接丢整批。

边界：

- `InvalidAccessKeyId`、权限、连接失败这类问题优先看运行环境和配置，不要直接归因脚本。
- 类别映射、字段结构、点云/图片路径等要开发查脚本和样例。

## PM 问：PM-check 是什么？

答法：

PM-check 是给 PM 做导入检查用的旁路产物，不是正式交付结果。它的作用是让 PM 按任务粒度预览或复查平台能否识别关键字段、帧数和标注结构。

历史口径：

- PM-check 目录不要和正式导出目录混在一起。
- JSONL 应保持“一行一个完整任务”，不要拆成一帧一行，除非当前工具明确要求。
- 多帧任务里常见检查点是 `timeSeries` 是否按 attachment 总帧数补齐，并保留 appear/value/disappear 语义。

需要开发确认：

- PM-check 是否能直接导入当前项目。
- 当前任务的帧数、嵌套 children、标注类型是否已完整覆盖。

## PM 问：导出统计里的帧数为什么和总帧不一样？

答法：

先确认统计口径。导出统计可能会排除无效帧、空标注帧、没有点云结果的帧，或者按任务级 JSONL 和拆帧结果使用不同统计口径。不能只用“总帧数”判断导出少了。

让 PM 提供：

- 统计脚本或工具名称。
- 输入 JSONL/Excel/导出目录。
- 任务 ID 样例。
- 是否包含 invalidFrame 或空帧。
- PM 期望统计的是任务数、帧数、实例数还是类别数量。

## PM 问：结果能不能直接交付客户？

答法：

不能只看工具是否跑完。正式交付至少要看：

- 文件能否解析。
- 数量是否对得上。
- 字段和客户样例是否一致。
- 类别/属性映射是否正确。
- 抽样可视化或回灌是否正常。
- 是否存在客户口径未确认项。

风险高时：

使用“需要开发确认”的结论。可以说“当前结果已生成，但正式交付前还需要校验”，不要说“可以发客户”。

## PM 问：页面使用说明要不要写部署命令？

答法：

PM 使用说明只写页面动作：打开哪个页面、填什么字段、点哪个按钮、等待什么提示、最终拿哪个结果链接。部署、conda、服务启动、日志路径属于开发/运维材料，不应混进 PM 使用说明。
