# 真实平台报错口径

面向 PM 解释平台导入/回灌时的真实错误文本。目标不是让 PM 判断根因，而是让 PM 知道这类报错大概指向什么、该补齐哪些材料、什么时候必须找开发。

## 总口径

- 平台已经报出具体字段或操作项时，优先按“任务数据和当前项目模板/操作项不一致”来收集证据，不要直接说脚本坏了。
- 同一个中文标签看起来一致，不代表平台能接受；平台通常还会校验内部 `key`、节点顺序、children 结构、必填项、slot 类型。
- PM 可以判断“材料是否齐”，不能自行判断“应该改哪个 key / 能不能继续导入 / 能不能交付”。

## `uuid` / `uniqueIdentifier` 类

PM 解释：

平台用它区分一条任务记录。如果缺失、重复、位置不对，或当前项目要求的 ID 格式不满足，平台可能无法创建任务或把任务识别成冲突记录。

常见原因：

- 多个 JSONL 行复用了同一个任务 ID。
- 合并、拆分、复制历史任务时没有重新生成 ID。
- 字段应该在 `metadata.uniqueIdentifier`，却被写到顶层或其他位置。
- 当前客户/项目要求 UUID v4，但生成结果不是合法 UUID。
- `metadata.title` 和任务 ID 的生成规则被改过，导致 PM 看到任务名和平台记录对不上。

PM 要收集：

- 完整报错截图和原文。
- 失败 JSONL 的 1-2 行样例。
- 该 JSONL 的总行数、是否由多个文件合并、是否分包。
- 如果提示重复，提供相邻几行或整包给开发做唯一性检查。
- 这批任务的标题来源规则，例如来源文件名、TXT 清单、导航 JSON 名。

升级条件：

- 需要判断字段应该放在哪里、是否要批量刷新 ID、是否影响已导入任务时，必须找开发确认。

## `标注结果对应操作项不存在`

常见原文：

- `无3d灯箱 -> 无3d灯箱：box2d-[f43b0] 标注结果对应操作项不存在`
- 类似 `annotation`、`operator`、`操作项不存在`、`key 不存在` 的错误。

PM 解释：

JSONL 里带了某个标注字段，但当前项目模板里找不到它对应的操作项。不是“中文标签没有这个类”这么简单，平台看的是内部操作项 key。

常见原因：

- 用了旧项目或另一个项目的导入/反导入结果。
- `annotations.json` 和 `operators.json` 不是当前项目配套的一组。
- 标签中文名类似，但内部 key 不同，例如旧项目的 `box2d-[f43b0]` 到新项目变成了另一个 `box2d` key。
- 平台项目模板改过，但导入数据还是按旧模板生成。
- 脚本里使用了历史硬编码映射，没有按当前项目模板重新适配。

PM 要收集：

- 完整报错截图，尤其是报错里点名的 label、key、节点路径。
- 项目 ID、任务类型、池子 ID、标签模板或操作项版本。
- 导入 JSONL 中对应的一行样例。
- 这批数据是新生成、旧项目反导入，还是复用了历史输出。
- 如果有，提供当前项目导出的 `annotations/operators` 配置给开发比对。

升级条件：

- 出现该错误时不要反复重试导入。需要开发对比 JSONL 里的 `annotations` 和当前项目 `operators` 的 key 是否一致。

## `annotation 与操作项不匹配`

PM 解释：

这是“标注结果的数据结构”和“平台当前任务模板”对不上。可能顶层操作项对不上，也可能 children、slot 类型、输入控件类型对不上。

常见原因：

- `annotations[i]` 和 `operators[i]` 本应一一对应，但脚本用了旧下标或旧映射。
- 只按中文 label 对齐，忽略了同名 label 下不同的内部 key。
- 某个 children 从旧模板复制过来，当前模板需要另一套 children。
- 预标注或回灌结果里出现了当前项目没有配置的子项。

PM 要收集：

- 平台报错原文。
- 当前项目模板/操作项信息。
- 失败样例 JSONL。
- 说明这批数据是“导入新任务”“预标注导入”还是“反导入/回灌标注结果”。

升级条件：

- 只要涉及改映射、改模板、重跑脚本、确认是否可继续导入，都必须找开发。

## `节点顺序和原操作项不一致`

常见原文：

- `交通标志 -> 交通标志 -> 功能 节点顺序和原操作项不一致`

PM 解释：

平台找到了类似的标签或节点，但它在当前模板中的顺序、层级或内部 key 和导入数据不一致。这个问题经常发生在“旧项目结果导入新项目”或“两个项目看起来操作项差不多”的场景。

常见原因：

- 旧模板和新模板有同名节点，但 children 顺序变了。
- 某个属性从单选变成多级选择，或控件类型发生变化。
- 脚本只按 label 名称迁移，没有按当前项目的 operator key 和 children 顺序重建。

PM 要收集：

- 报错里完整的节点路径，例如 `交通标志 -> 功能`。
- 当前项目模板截图或配置。
- 导入数据来源项目和目标项目。
- 失败 JSONL 的一行样例。

升级条件：

- 需要开发确认“是否能通过模板重建修复”，PM 不要自己判断两个项目模板“差不多就能用”。

## `annotations` / `children` / `timeSeries` 结构类

PM 解释：

平台能读到 JSON，但读不懂其中某层标注结构。常见在多帧任务、嵌套属性、点级预标注、2D/3D 组合任务中。

常见原因：

- `annotations` 层级不在当前工具约定的位置。
- children 为空或缺少当前项目要求的节点。
- `slotsChildren`、`children`、`slots`、`timeSeries` 混用错层级。
- 多帧任务没有按 attachment 帧数补齐 timeSeries。
- 一行一个任务和一帧一行的 JSONL 粒度混淆。

PM 要收集：

- 完整报错截图。
- 失败阶段：上传、解析、创建任务、提交预标注、回灌标注结果。
- 失败 JSONL 一行样例。
- 任务帧数、附件数量、是否多帧。
- 当前任务类型和模板。

升级条件：

- 结构类问题必须让开发看样例。PM 可以帮忙确认材料完整，但不要承诺“删掉某个 children 就能好”。

## PM 可直接回复模板

遇到真实平台报错时，可以这样回：

`这个报错不是单纯说明脚本坏了，更像是导入数据里的标注字段和当前项目模板/操作项没有对齐。你先不要重复导入，麻烦补一下完整报错截图、项目/任务/池子 ID、失败 JSONL 一行样例、当前模板或操作项信息，以及这批数据是新生成还是旧项目反导入。材料齐了以后需要开发对比 annotations 和 operators 的 key/节点顺序，再判断怎么修。`

如果是 ID 类报错，可以这样回：

`这个像任务唯一 ID 的问题。请先提供完整报错、失败 JSONL 样例、总行数、是否合包/分包，以及任务标题来源规则。是否需要刷新 uniqueIdentifier 或调整字段位置，需要开发确认后再处理。`
