# Startask I/O 契约审计 Skill 使用指南

> 本文面向 Skill 使用者，帮助你判断何时调用以及如何理解审计结果。Codex 的实际触发条件和执行规则以 [SKILL.md](SKILL.md) 为准；本文不是第二套执行合同。

## 一分钟了解

`startask-io-contract-audit` 用于在 Startask/Stardust 导入、预标、导出、回流或交付前审计数据合同。

它不会直接替你实现解析器，而是先回答以下问题：

- 客户规格、真实样例、operator/schema、平台记录、适配代码和校验器是否一致？
- 字段映射、坐标系、时间轴、ID、点顺序和数据血缘是否已有可靠依据？
- 哪些结论已经确认，哪些只是推断，哪些仍然冲突或缺失？
- 当前证据最多能支持到哪个验证等级，是否可以进入实现或对外交付？

## 适用场景

遇到以下情况时，建议调用本 Skill：

- 新的导入、预标、导出或回流需求，客户合同尚未冻结。
- 规格、样例、operator、平台结构、代码或校验器互相矛盾。
- 标签映射、缺失值策略、坐标变换、时间顺序、对象 ID、点顺序或血缘不明确。
- 需要判断“可以开发了吗”“本地验证是否足够”“能否交付客户”。
- 已完成实现，但需要重新审计受影响字段并确认验证边界。

## 不适用场景

以下任务通常不需要调用本 Skill：

- 合同已经确认，只需按既定规则完成常规实现。
- 与 Startask/Stardust 无关的普通文件转换或代码审查。
- 仅想查询某个格式的固定语法，没有跨证据冲突或交付判断。
- 希望仅凭本地脚本结果证明平台端或客户环境已经验收成功。

合同已经冻结后，导入实现可使用 `startask-import-playbook`，导出实现可使用 `startask-export-playbook`；如果实现改变了合同字段或验证结论，再回到本 Skill 复审。

## 快速调用

在 Codex 中显式引用 Skill 名称，并说明任务范围、允许的操作和期望结论：

```text
$startask-io-contract-audit 请对这项 Startask 导入或导出需求进行只读契约审计：
盘点规范、真实样例、operator、平台记录、代码和校验器；
列出关键字段矩阵与冲突归属；
在需要我确认的业务映射处停止；
给出当前连续最高验证闸门和不可证明事项。
```

为了减少反复确认，最好同时说明：

- 任务类型：导入、预标、导出、回流或交付验收。
- 数据类型：如 TEXT、IMAGE、PointCloud_4D 或 semantic-segmentation3d。
- 允许范围：只读分析、允许修改的文件、是否允许访问或写入远端。
- 目标结论：方案评审、实施准备、本地验证、平台验证或客户验收。

## 需要准备的证据

尽可能提供下面六类证据。缺失项不应被默认值或历史经验悄悄替代：

| 证据类型 | 典型内容 | 主要证明什么 |
|---|---|---|
| 客户规格 | 字段说明、配置文件、验收标准 | 业务语义和目标合同 |
| 真实样例 | 脱敏源文件、目录结构、实际值域 | 真实布局、编码、缺失情况和数据范围 |
| operator/schema | 当前 operator tree、节点定义、枚举 | 平台节点结构、顺序和输入值类型 |
| 平台记录 | 已接受的 attachment、annotation、slot 等 | 平台实际结构和行为 |
| 适配代码 | importer、prelabel、exporter、serializer | 当前转换和序列化行为 |
| 校验依据 | 官方 validator、已接受输出、验收结果 | 目标结构和交付判定 |

外部路径、对象地址和样例必须脱敏，不要把凭证、签名 URL、私有对象键或客户敏感数据粘贴到审计结果中。

## 你会得到什么

标准审计结果应先给出结论和 `readiness`，再包含：

1. 任务与授权边界，以及六类证据清单。
2. 关键字段契约矩阵；每行标记为 `CONFIRMED`、`INFERRED`、`CONFLICT` 或 `MISSING`。
3. 冲突登记；每条冲突只有一个主要归属层，跨层问题拆成相互关联的多条记录。
4. 需要你确认的业务决策，以及不同选择对实现、远端状态和验证结论的影响。
5. 实施范围卡，包括允许修改的文件、不可变入口、输入输出边界、远端 I/O 边界和失败策略。
6. `highest_passed_gate`、更高等级的 `not_verified`、阻断项和下一步。

当关键证据缺失、权威冲突未解决，或要求的结论超过现有证据时，正确结果应是 `BLOCKED`，而不是继续猜测并生成代码。

## G0–G6 验证等级

验证必须从 G0 开始连续通过，不能用某个孤立的高等级结果跳过中间等级。

| 等级 | 含义 | 最低证明范围 |
|---|---|---|
| G0 | 证据盘点 | 已记录存在、缺失、过期、冲突和不适用的证据 |
| G1 | 静态验证 | 语法、导入、配置或基础 schema 检查通过 |
| G2 | 结构验证 | operator/annotation 的层级、顺序、类型和数量符合冻结合同 |
| G3 | 真实小样本 | 真实字段、枚举、时间轴、数量和序列化值符合合同 |
| G4 | Round-trip 或可视化 | 坐标逆变换、RLE、点索引或几何可视化满足声明的不变量 |
| G5 | 平台端到端 | 实际平台导入、默认视图、预标、导出或平台校验通过 |
| G6 | 客户验收 | 客户环境、官方校验器或正式验收证据通过 |

常见就绪结论：

- `DESIGN_ONLY`：只有设计或范围，G0 尚未完成。
- `READY_FOR_IMPLEMENTATION`：G0 完成、合同冻结、没有关键阻断，但实现验证尚未通过。
- `LOCALLY_VERIFIED_ONLY`：最高只到 G1–G4，不能表述为平台或客户成功。
- `PLATFORM_VERIFIED`：G0–G5 连续通过，G6 尚未通过。
- `CLIENT_ACCEPTED`：G0–G6 连续通过。
- `BLOCKED`：关键冲突、证据缺失、环境不可用或必需检查失败，阻止下一项结论。

## 示例

### 应当调用

```text
$startask-io-contract-audit 审计 OCC 点云预标中的客户 semantic ID、
operator 支持类别和输出 annotation 之间的合同。
如果缺少客户 config.json，请明确哪些能够确认、哪些必须阻断，不要修改代码。
```

这个任务存在跨证据映射和交付边界问题，应该先审计再决定是否实现。

### 不应调用

```text
Startask 的 box2d 合同已经确认且 operator 不变，
请按现有导出 Playbook 给已定位函数补一个普通 box2d 解析分支。
```

这个任务属于冻结合同下的常规实现，应直接使用相应 Playbook；除非实现过程中发现新的合同冲突。

## 能力边界

- 本 Skill 是契约审计与交付闸门，不是客户数据解析器或平台操作机器人。
- G0–G4 只能证明相应的本地、结构、样例或 round-trip 边界。
- 没有实际平台证据时不能声明 `PLATFORM_VERIFIED`；没有客户验收证据时不能声明 `CLIENT_ACCEPTED`。
- 历史项目经验、现有代码和默认值都只能作为证据，不能自动替代当前任务的业务权威。
- 审计结果应明确“已证明什么”和“尚未证明什么”，避免把计划中的验证写成已经完成。
